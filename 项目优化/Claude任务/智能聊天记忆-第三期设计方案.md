# 智能聊天记忆第三期设计方案：跨会话相关记忆召回

## 1. 目标

第三期解决“用户在大量过去聊天中已经讨论过某件事，但新会话不知道应当找哪一段历史”的问题。

第三期不是把全部旧聊天塞给模型，而是在用户明确允许的前提下，从同一用户的历史记忆中选择少量与当前问题真正相关、可信且仍有效的信息。

```text
第一期：系统知道用户偏好什么。
第二期：系统知道当前聊天进行到哪里。
第三期：系统能在合适时想起以前哪段已确认的内容与当前问题有关。
```

## 2. 用户与使用场景

### 2.1 用户故事

1. 作为用户，我新开聊天说“继续设计导师审核”，系统应能找到我曾确认过的相关设计结论。
2. 作为用户，我不希望系统把所有旧对话都拿出来，也不希望无关历史突然影响当前回答。
3. 作为用户，我希望知道系统在本次回答中使用了哪些历史记忆，并可以纠正或删除它们。
4. 作为用户，我希望能关闭“跨会话历史召回”，同时保留第一期的基础偏好。
5. 作为用户，我希望项目类记忆只在对应项目中被召回，而不是在所有普通聊天中出现。

### 2.2 示例

用户在三个月前的会话中确认：

```text
项目：智能聊天记忆
决策：第一期只做用户偏好；第二期做会话摘要；第三期再做跨会话召回。
```

今天新建聊天，用户问：

```text
第三期是否要加入向量检索？
```

系统可以召回这条已确认决策，并显示：

```text
已引用相关历史记忆：
“智能聊天记忆三期规划”（来自 2026-10-13 的会话确认）
```

系统不应顺带召回用户在别的会话中讨论 Python 报错、日常闲聊或无关项目的信息。

## 3. 记忆范围与类别

第三期在原有个人偏好、会话上下文之外，增加可被跨会话召回的记忆：

| 类别 | 含义 | 典型来源 |
|---|---|---|
| 已确认决策 | 用户已明确确认的长期决定 | 用户确认卡片、项目确认动作 |
| 稳定背景 | 长期有效的用户或项目背景 | 用户设置、用户确认 |
| 项目规则 | 某个项目内有效的约束 | 项目设置、审核结论 |
| 历史结论 | 某次会话形成且被确认的结论 | 会话摘要中的确认事项，经用户确认后提升 |
| 待办与目标 | 可跨会话继续的任务 | 用户明确保存的待办 |

不允许跨会话召回：

- 未确认的模型猜测；
- 原始私密聊天全文；
- 已删除、停用、过期或被替代的记忆；
- 临时对话内容；
- 其他用户的任何信息。

## 4. 功能设计

### 4.1 跨会话历史召回开关

在“我的记忆”页增加：

```text
跨会话相关记忆
[开启 / 关闭]

说明：开启后，系统会在新会话中仅召回与你当前问题相关的、已确认的历史记忆。
```

用户可以分别配置：

```text
[x] 使用个人偏好
[x] 使用已确认的历史决策
[x] 使用项目内记忆
[ ] 使用一般历史会话结论
```

默认只开启“个人偏好”和“已确认决策”；一般历史会话结论需要用户主动开启。

### 4.2 相关记忆展示

当一次回答使用了跨会话记忆时，在回答下方显示可展开提示：

```text
本次参考了 2 条历史记忆  [查看]
```

展开后显示：

```text
1. 智能聊天记忆三期规划
   内容：第三期再做跨会话相关记忆召回
   来源：会话“智能聊天记忆设计”，2026-10-13
   状态：已确认
   [本次不使用] [编辑] [删除]
```

用户可以对单条记忆采取动作：

```text
本次不使用：仅本次回答及当前会话忽略该记忆
停用：未来不再被召回，但保留记录
编辑：修正内容，保留修订历史
删除：彻底移除，未来不可召回
```

### 4.3 从会话摘要提升为长期记忆

会话摘要中出现“已确认事项”时，用户可点击：

```text
[保存为跨会话记忆]
```

系统展示：

```text
准备保存：
“第三期启用跨会话相关记忆召回。”

范围：个人 / 某个项目
类别：决策 / 背景 / 规则 / 待办
有效期：长期 / 指定日期前

[确认保存] [取消]
```

系统也可以提出“值得保存”的候选卡片，但只能提出，不能自动升级为跨会话记忆。用户不确认时不保存。

### 4.4 项目范围记忆

当用户在明确的项目空间内工作时，项目记忆仅在该项目中参与召回。

```text
个人范围：中文回答、偏好工程化解释。
项目范围：本项目不做自动模型路由；导师要求证据卡审核。
```

普通智能聊天默认不展示项目范围记忆；用户需要明确选择项目或提及项目后才可使用。

### 4.5 冲突与过期

如果存在相互冲突的历史记忆：

```text
旧决策：不做自动模型路由
新决策：下一版本恢复自动模型路由
```

系统应：

1. 优先使用最新且已确认的决策；
2. 将旧决策显示为“已被替代”；
3. 不把两条冲突内容同时当作事实注入回答；
4. 在用户查看历史时保留完整修订链。

对于待办、短期项目约束等内容，用户可设置有效期；到期后不再自动召回。

## 5. 召回体验规则

第三期必须满足“少而准、可解释、可撤销”。

每次回答：

- 只使用少量最相关记忆；
- 只从当前用户有权访问的范围中选择；
- 优先已确认、未过期、未被替代的信息；
- 不因相关性相似就泄露其他会话的原始内容；
- 若当前用户消息与旧记忆冲突，以当前消息为准；
- 对用户展示本次使用了哪些跨会话记忆。

新会话的上下文可以表现为：

```text
个人偏好
+ 当前会话摘要（新会话可为空）
+ 0～数条相关历史记忆
+ 当前用户问题
+ 知识库检索结果（如适用）
```

历史记忆不能替代知识库引用。知识库回答中的事实仍应由检索文档支撑。

## 6. 人工验收测试用例

| 编号 | 操作 | 预期结果 |
|---|---|---|
| P3-01 | 在会话 A 将一条已确认决策保存为跨会话记忆 | 新会话中相关问题可使用该决策 |
| P3-02 | 新会话提出与该决策无关的问题 | 系统不展示、不使用该决策 |
| P3-03 | 用户开启跨会话召回后，询问与旧项目相关的问题 | 回答使用少量相关记忆，并显示“本次参考了哪些记忆” |
| P3-04 | 点击某条已使用记忆的“本次不使用” | 当前会话后续回答不再使用该记忆；原记录仍保留 |
| P3-05 | 停用一条跨会话记忆后，新开相关会话 | 系统不再召回该记忆 |
| P3-06 | 删除一条跨会话记忆后，新开相关会话 | 系统不再召回，查看历史列表也不再显示 |
| P3-07 | 创建新旧两条相互冲突的决策 | 默认只使用最新且已确认的决策；旧记录标记为已替代 |
| P3-08 | 当前消息明确反驳旧记忆 | 当前消息优先；旧记忆不应强行影响答案 |
| P3-09 | 在项目 A 保存项目规则，再进入项目 B | 项目 B 不能召回项目 A 的规则 |
| P3-10 | 在普通智能聊天中不选择项目 | 项目级记忆默认不出现 |
| P3-11 | 关闭跨会话相关记忆 | 新会话不召回历史决策；第一期个人偏好仍按用户开关工作 |
| P3-12 | 关闭“一般历史会话结论”但保留“已确认决策” | 只使用已确认决策，不使用普通会话摘要中的内容 |
| P3-13 | 让系统提出一条“值得保存”的候选后选择取消 | 不产生跨会话记忆 |
| P3-14 | 用户 A 和用户 B 有相似聊天主题 | 任何跨会话召回均只能来自当前用户自己的历史 |
| P3-15 | 在知识库对话中使用历史记忆 | 历史记忆只提供用户或项目背景；答案的客观事实仍显示知识库引用 |

## 7. 第三期开通标准

第三期完成后，用户应能清楚回答：

```text
系统为什么想起这件事？
它来自哪次历史记录？
我能否只让它本次不使用、以后停用或彻底删除？
这条记忆属于我个人，还是只属于某个项目？
```

如果系统无法解释本次使用了哪条历史记忆，或用户无法撤销它，则跨会话相关记忆不应上线。
