# 智能聊天记忆第二期设计方案：会话私有上下文

## 1. 目标

第二期解决长对话“聊到后面忘记前面”的问题。

它让每个聊天窗口保存自己的主题、已确认事项、当前目标和待解决问题；这些内容只属于当前会话，默认不会带入其他聊天窗口。

```text
第一期回答：系统知道“这个用户偏好怎样被回答”。
第二期回答：系统知道“这个聊天窗口已经讨论到哪里”。
```

第二期继续沿用第一期的个人偏好记忆，同时新增会话私有上下文。

## 2. 用户与使用场景

### 2.1 用户故事

1. 作为用户，我希望与助手聊很久以后，它仍知道本次讨论的目标和已经确认的结论。
2. 作为用户，我希望会话 A 的细节不进入会话 B。
3. 作为用户，我希望能看见、纠正或清空本会话的摘要。
4. 作为用户，我说“记住这个”时，系统应让我确认记住的范围。
5. 作为用户，我希望可以开启临时对话，使本次对话不生成会话摘要。

### 2.2 关键示例

会话 A：讨论智能聊天记忆。

```text
已确认：第一期只保存用户偏好。
已确认：第二期新增会话摘要。
当前问题：摘要由谁生成、如何更新。
```

会话 B：讨论 Python 报错。

```text
会话 B 不应知道会话 A 中“第二期新增会话摘要”的讨论细节。
```

## 3. 会话上下文内容

每个会话保存一份当前有效的会话上下文：

```text
会话主题：这次主要讨论什么
会话目标：用户希望得到什么结果
已确认事项：用户或助手已经明确达成的结论
限制条件：本会话的临时约束
待解决问题：尚未回答或尚未完成的事项
会话摘要：对较早内容的简洁回顾
```

会话上下文不是正式的长期事实库。它只是帮助本会话连续进行的“便签”。原始聊天记录仍然保留，摘要可被重建或清空。

## 4. 功能设计

### 4.1 自动摘要

系统在以下情况更新会话摘要：

- 对话达到一定长度；
- 较早消息占据过多上下文；
- 用户确认了重要决定；
- 用户明显切换到新子主题；
- 用户手动点击“更新本会话摘要”。

更新后的摘要应采取固定结构：

```text
当前主题：
当前目标：
已确认事项：
限制条件：
待解决问题：
```

摘要只压缩较早的历史内容。最近的关键消息仍以完整原文参与当前回答，避免摘要丢失细节。

### 4.2 会话上下文抽屉

聊天窗口顶部显示：

```text
智能聊天 · 本会话上下文已开启
```

点击后打开抽屉：

```text
本会话上下文

主题：智能聊天记忆设计
目标：确定三期功能边界

已确认事项
- 第一期只做个人偏好记忆
- 暂不做自动模型路由

待解决问题
- 会话摘要由谁生成、何时更新

[更新摘要] [编辑摘要] [重置本会话上下文]
```

用户编辑摘要后，本会话应立即使用编辑后的内容；系统后续自动更新时应保留用户明确修改的关键结论，不能静默覆盖。

### 4.3 “记住”与“忘记”确认卡片

当用户明确表达如下意图时：

```text
记住：本项目不用自动模型路由。
以后默认中文回答。
忘记：我偏好简短回答。
```

系统显示确认卡片，而不是直接写入：

```text
你希望保存以下内容：
“本项目不用自动模型路由。”

保存范围：
( ) 仅本会话
( ) 作为跨会话个人偏好

[确认保存] [不保存]
```

默认推荐范围：

| 内容类型 | 默认范围 |
|---|---|
| “本次任务”“当前项目”“这次聊天” | 仅本会话 |
| “以后默认”“我习惯”“我偏好” | 跨会话个人偏好 |
| 含义不明确 | 不预选，要求用户选择 |

“忘记”也必须展示将删除或重置的对象，避免误操作。

### 4.4 临时对话

用户可在新建聊天时选择：

```text
临时对话
```

临时对话行为：

- 可以读取个人偏好，用户也可选择完全不读取；
- 不创建、更新或保留会话摘要；
- 退出后不保留会话私有上下文；
- 不允许通过“记住”写入个人偏好，除非用户显式离开临时模式并再次确认。

### 4.5 知识库对话

知识库对话也拥有独立的会话上下文。

```text
知识库文档：外部证据，按本次问题检索。
会话摘要：本窗口此前问过什么、已经解释过什么。
个人偏好：用户偏好怎样理解和呈现答案。
```

知识库文本不能触发“记住”功能。只有用户明确提出、或用户在界面中确认的内容才可写入记忆。

## 5. 回答时的上下文规则

每次回答按以下顺序组织信息：

```text
平台规则
当前用户消息
本会话上下文摘要
最近关键原始消息
个人偏好
知识库检索结果（仅知识库对话）
```

本会话中用户的新要求，优先于摘要中的旧内容。

如果摘要与最近原始消息矛盾，应以用户最新的明确表达为准，并在后续摘要更新中修正旧结论。

## 6. 人工验收测试用例

| 编号 | 操作 | 预期结果 |
|---|---|---|
| P2-01 | 在一个会话中连续讨论多个回合，并明确两条结论 | 会话抽屉中出现正确的主题和已确认事项 |
| P2-02 | 对话达到自动摘要条件 | 系统生成或更新摘要；最近消息仍完整可见 |
| P2-03 | 依据长会话早期已确认事项继续追问 | 助手能延续该事项，不要求用户重复说明 |
| P2-04 | 新建另一个会话并提问无关问题 | 新会话不出现旧会话的主题、结论或待办 |
| P2-05 | 在会话 A 编辑摘要中的结论 | 后续会话 A 回答采用修改后的内容 |
| P2-06 | 点击重置本会话上下文 | 摘要、主题、待办被清空；个人偏好不受影响 |
| P2-07 | 输入“记住：本次任务不用自动路由” | 出现范围选择卡片；默认仅本会话 |
| P2-08 | 输入“以后默认中文回答”并确认跨会话保存 | 新建智能聊天和知识库对话均使用中文 |
| P2-09 | 在确认卡片选择“不保存” | 不新增个人偏好，也不新增会话已确认事项 |
| P2-10 | 创建临时对话并长时间交流 | 不生成可在之后恢复的会话摘要 |
| P2-11 | 在临时对话输入“记住：默认中文” | 系统阻止直接写入，并说明需退出临时模式后确认 |
| P2-12 | 在知识库对话中阅读文档片段 | 文档内容不自动成为个人或会话记忆 |
| P2-13 | 旧摘要称“使用中文”，最新消息要求英文 | 本次回答使用英文；后续摘要更新为最新约束 |
| P2-14 | 用户 A 与用户 B 各自有同名会话 | 不能互相读取或修改对方会话摘要 |

## 7. 第二期开通标准

第二期完成后，用户应能：

```text
知道系统为何还能记住本次较早的讨论；
查看并纠正本会话摘要；
让会话 A 和会话 B 保持隔离；
明确选择一条信息是“只记本会话”还是“跨会话记住”。
```
