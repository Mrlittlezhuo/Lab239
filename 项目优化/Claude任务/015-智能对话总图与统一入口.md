## 2. 背景

任务 012 已经能够在 Chat API 外层识别普通对话、知识库检索、单工具任务和复杂任务，
但目前仍由一组 if/else 直接选择普通聊天或 Agent Run。WebUI 也仍将“自动 Agent”、
“普通对话”和“手动调试”并列展示，用户需要理解内部运行方式。

任务 014 已将多步骤 Agent 内部迁移为正式 LangGraph 状态图，并具备持久 checkpoint、
恢复、取消和 legacy 回退。现在需要在它上方增加一层轻量的“智能对话总图”，统一一次
对话请求的路由与分发：

    用户问题
       → 意图路由
       ├─ 直接回答
       ├─ 知识库任务
       ├─ 单工具任务
       └─ 多步骤 Agent

总图负责选择路径和统一输出，具体能力继续复用现有 chat、意图路由、工具注册、
知识库工具和 Agent Runtime，不另建第二套实现。

本任务完成的是通用智能对话入口。研究项目、论文记录、证据卡片和研究工作流属于后续
任务 016，不在本任务提前实现。

## 3. 目标

1. 建立真实的 LangGraph 智能对话总图，让路由与四类执行分支具有清晰节点和条件边。
2. 将普通回答与自动 Agent 合并为面向用户的“智能对话”入口。
3. 知识库和单工具任务走受限的一步 Agent 路径，复杂任务走现有多步骤 LangGraph Agent。
4. 保持现有流式/非流式响应、会话、长期记忆、Agent 时间线和取消能力兼容。
5. 保留普通直聊和手动 Agent 的后端兼容入口，供高级调试与回退使用。
6. 为后续“论文研究”分支留下清晰扩展点，但不实现研究业务。

## 4. 目标架构与职责

建议的总图职责如下，具体节点命名可根据现有代码调整：

    route
      ├─ direct_answer
      ├─ knowledge_task
      ├─ single_tool_task
      └─ multi_step_agent
              ↓
        normalize_result

要求：

- route 节点只调用一次现有意图路由，并保存经过校验的 RouteResult；
- direct_answer 复用现有 chat 流程，不创建 AgentRun；
- knowledge_task 只向现有 Agent Runtime 提供知识库检索工具，并限制为一步工具任务；
- single_tool_task 只提供路由选中的单个有效工具，并限制为一步工具任务；
- multi_step_agent 复用任务 014 的默认 LangGraphRuntime，不复制计划执行循环；
- normalize_result 统一路由信息、执行路径、会话 ID、Agent Run 和错误语义；
- 图必须具有真实分支节点和条件边，不能把原有 if/else 整体包装进一个节点。

总图是一次对话请求的短生命周期编排层，不要求新增第二套持久 checkpoint。需要恢复的
多步骤执行仍由任务 014 的 Agent Runtime checkpoint 负责。

## 5. 关键行为

### 5.1 路由映射

现有 RouteResult 继续作为判断依据：

| 意图/复杂度 | 执行分支 |
|---|---|
| general、unknown 或统一回退 | direct_answer |
| kb_search | knowledge_task |
| single_tool 或 single | single_tool_task |
| complex 或 multi | multi_step_agent |

如现有结构不足以表达最终执行分支，可以兼容地增加 execution_mode 等扩展字段；不要破坏
任务 012 已有 path、intent、complexity 和 candidate_tools 字段。

### 5.2 一步任务与多步骤任务

- 知识库任务继续使用 search_local_knowledgebase 和现有公共知识库边界，不复制 kb_chat
  或向量检索实现；
- 单工具任务只允许调用路由选中的一个实际可用工具；
- 两类一步任务均复用 Agent Run/Step 轨迹，但最多执行一个工具步骤；
- 多步骤任务继续使用正常步数限制、重规划、取消、checkpoint 和恢复；
- 候选工具为空、工具已失效或路由结果不一致时，在开始工具执行前可控回退直接回答；
- Agent Run 或工具已经开始后发生失败，应返回明确失败状态，不能再静默切换路径造成
  工具重复执行。

### 5.3 流式与非流式输出

- 流式响应先给出一次路由/执行分支事件，再透传所选分支的内容与 Agent 事件；
- 非流式响应包含 conversation_id、route_result 和 execution_mode；
- 使用 Agent 的分支继续返回 agent_run、计划和步骤信息；
- 一次请求只创建一条用户消息，并且只写回一个最终回答；
- 不向用户输出模型隐藏思维链。

### 5.4 WebUI

- 普通用户的主入口命名为“智能对话”，不再要求在“普通对话”和“自动 Agent”之间选择；
- 系统在智能对话内部自动决定直接回答或 Agent 执行；
- 手动工具、MCP、强制 Agent Run 和强制普通直聊可以保留在高级/调试设置中；
- 现有知识库问答入口、侧边栏、Agent 时间线和取消入口不得消失；
- 界面只展示简短的意图名称和实际执行分支。

后端已有 auto_agent、agent_run 等参数应保持兼容，避免旧客户端突然失效。
