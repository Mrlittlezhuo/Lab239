# 论文研究助手：目标产品与功能架构

## 1. 文档目的

本文定义 Langchain-Chatchat 后续优化的统一产品方向和目标功能架构，用来回答：

1. 项目最终要做成什么产品；
2. 用户使用它完成什么工作；
3. 各功能模块如何协作；
4. 哪些能力复用现有实现，哪些能力需要补充；
5. 后续任务应按什么边界和顺序拆分。

本文是产品和功能总纲，不直接规定每个源码文件如何修改。具体数据库、API、Agent
流程和 WebUI 实现应从本文继续拆分独立设计与任务文档。

## 2. 产品定位

项目的目标定位是：

> 一个支持本地私有化部署、以证据和引用为中心、能够持续保存研究进度的论文研究助手。

它面向学生、研究人员和技术开发者，帮助用户围绕一个研究问题完成：

- 管理研究项目；
- 检索本地与公开论文；
- 筛选和阅读论文；
- 提取结构化证据；
- 比较不同论文的方法与实验；
- 生成可追溯引用的研究报告；
- 保存进度并在后续会话中继续研究。

项目不定位为自动代写论文工具，也不以完全自主、不可控的通用 Agent 为目标。
系统负责提高检索、阅读、比较和整理效率，研究结论仍由用户检查和确认。

## 3. 目标用户与核心场景

### 3.1 目标用户

- 需要完成文献调研的本科生和研究生；
- 需要快速进入一个技术方向的研发人员；
- 需要长期维护专题资料的个人研究者；
- 需要在本地环境处理论文和内部资料的用户。

### 3.2 核心场景

用户创建一个“LLM Agent 长期记忆方法研究”项目，输入：

> 检索近三年关于长期记忆 Agent 的代表性论文，比较记忆存储、检索方法、
> 使用的数据集、实验结果与主要局限。

系统应当能够：

1. 生成可编辑的研究范围和检索计划；
2. 检索本地知识库、ArXiv及允许的互联网来源；
3. 合并和去重候选论文；
4. 按相关度、年份和全文可用性筛选论文；
5. 从论文中提取方法、数据集、指标、结论和局限；
6. 建立结论与原文片段、页码、章节之间的关系；
7. 生成论文比较表和带引用的 Markdown 报告；
8. 允许用户查看引用原文、排除论文、补充检索和重新生成报告；
9. 保存所有进度，下一次登录后继续同一研究项目。

## 4. 产品形态

系统保留三种主要使用入口，共享用户、会话、模型、知识库、工具和基础 Agent 能力。

| 使用入口 | 作用 | 是否创建研究项目 |
|---|---|---|
| 智能对话 | 自动判断直接回答、知识库检索、单工具或多步骤Agent | 否 |
| 知识库问答 | 针对已有资料进行一次性问答 | 否 |
| 论文研究 | 围绕研究问题持续检索、阅读、整理和报告 | 是 |

普通对话和自动Agent不再作为两个面向用户的入口。用户只需要进入“智能对话”并
提出问题，系统通过意图路由自动决定：

- 闲聊、解释、翻译和改写等请求直接回答，不创建Agent Run；
- 明确依赖资料的问题自动执行知识库检索；
- 明确的单一能力请求调用对应工具；
- 需要连续操作的请求进入多步骤Agent Run；
- 识别为长期论文研究时，引导用户新建或选择研究项目，而不是在普通会话中生成一份
  无法继续维护的一次性报告。

这里合并的是产品入口，后端仍保留“直接回答”和“Agent执行”两条运行路径，以避免
所有请求都承担Agent规划和工具调用开销。手动开启Agent、手工选择工具等能力保留在
开发者或高级调试设置中，不作为普通用户的主要交互方式。

论文研究是项目的核心业务场景；知识库问答保留为用户明确指定知识库范围时的快捷入口。

## 6. 核心业务模块

### 6.1 用户、会话与研究项目

现有用户和会话系统继续作为身份与聊天基础。新增“研究项目”作为长期研究工作的
顶层容器。

研究项目至少包括：

- 项目名称和研究主题；
- 核心研究问题；
- 时间范围、语言和来源范围；
- 检索计划与检索历史；
- 已选择、已排除和待阅读论文；
- 证据卡片与论文比较维度；
- Agent 运行状态；
- 当前报告和历史报告版本。

研究项目属于当前用户。项目中的论文选择、证据、笔记和报告不能被其他用户读取。
现有永久知识库仍按当前规则全局共享。

### 6.2 文献检索与文献库

文献模块统一接收不同来源的结果，并转成统一的论文记录。

第一版来源：

- 现有本地知识库；
- 用户上传的 PDF；
- ArXiv 工具；
- 互联网搜索与网页阅读工具。

统一论文记录应包含：

- 标题、作者、年份和摘要；
- DOI、ArXiv ID或稳定来源地址；
- 论文来源；
- 本地文件与全文可用状态；
- 相关度和筛选状态；
- 与当前研究问题的关系。

文献模块负责标题、DOI和ArXiv ID去重，避免同一论文因为来源不同被重复阅读和引用。

### 6.3 论文解析与检索

论文进入系统后，应保留学术文档结构，而不是只生成无法定位来源的普通文本块。

目标能力包括：

- PDF元数据与正文解析；
- 章节、页码、表格标题等位置标识；
- 按章节和语义进行分块；
- 关键词与向量混合检索；
- Metadata过滤；
- Query Rewrite；
- Rerank；
- 返回可定位的原文片段。

第一版可以复用现有向量检索，引用定位和论文结构优先于一次性完成全部高级检索能力。

### 6.4 证据卡片

证据卡片是论文研究助手的核心中间产物。Agent 不直接从检索结果跳到最终报告，
而是先将论文内容整理为可检查的证据。

一张证据卡片包含：

- 对应的研究问题或子问题；
- 论文标识；
- 证据类型：方法、数据集、指标、结果、结论或局限；
- 原文片段；
- 页码、章节或块位置；
- 对原文的简短概括；
- 提取时间与提取模型；
- 用户确认、修改或否决状态。

最终报告的重要事实必须能够关联至少一张证据卡片。没有证据的内容应标记为推测、
研究建议或证据不足，不能伪装成论文结论。

### 6.5 论文比较

系统使用统一维度比较论文，默认比较：

- 研究目标；
- 核心方法；
- 记忆或检索结构；
- 数据集；
- 评价指标；
- 主要实验结果；
- 优点；
- 局限性。

用户可以增删比较维度。比较单元应引用证据卡片，而不是让模型脱离来源重新生成。

### 6.6 报告与引用

研究报告由以下部分组成：

1. 研究问题与范围；
2. 检索方法和筛选说明；
3. 研究方向概览；
4. 代表性论文；
5. 论文比较表；
6. 综合结论；
7. 不同观点与证据冲突；
8. 当前证据不足；
9. 后续研究建议；
10. 参考文献。

第一版支持 Markdown 报告和 BibTeX 导出。后续再增加 Word、PDF、APA和
GB/T 7714等格式。

每个引用应能够跳转到论文信息和对应证据。报告更新时保留版本，避免用户修改后
覆盖之前结果。

### 6.7 记忆与上下文

系统区分三种状态，避免不同研究项目互相污染：

| 状态类型 | 保存内容 | 生命周期 |
|---|---|---|
| 会话上下文 | 当前对话中的短期消息 | 当前会话 |
| 用户长期记忆 | 语言、报告格式、研究偏好 | 跨项目 |
| 项目研究状态 | 论文、证据、未解决问题和报告进度 | 当前研究项目 |

用户长期记忆不能代替项目状态；项目中尚未验证的研究结论也不能自动写入用户长期记忆。

## 7. 研究 Agent 功能架构

### 7.1 基本原则

- 第一版使用单 Agent，不依赖 Multi-Agent；
- 总体研究阶段由程序控制，阶段内部判断由模型完成；
- 工具调用必须来自当前实际可用工具；
- 关键产物写入数据库，不能只存在模型上下文；
- 每一步都应能够观察、失败、重试或继续；
- 事实性结论必须由证据支撑；
- 用户可以修改研究计划、排除论文和触发补充检索。

### 7.2 标准研究流程

```text
创建研究项目
  → 明确研究问题与范围
  → 生成研究计划和检索式
  → 用户确认或直接执行
  → 多来源检索
  → 论文标准化与去重
  → 候选筛选
  → 读取摘要/全文
  → 提取证据卡片
  → 检查证据覆盖和冲突
  ├─ 证据不足 → 补充检索/阅读
  └─ 证据充分 → 论文比较
  → 生成带引用报告
  → 用户审阅、追问和继续研究
```

### 7.3 与现有 Agent Run 的关系

现有 Agent Run/Step 继续负责：

- 规划与步骤记录；
- 工具调用；
- 观察结果；
- 重规划；
- 超时、失败和取消；
- WebUI执行时间线。

研究工作流在其上增加领域阶段、研究项目归属和结构化产物。不能另建一套完全独立的
Agent执行器。

FastJev继续负责智能对话内部的直接回答、知识库检索、单工具任务、复杂任务和论文
研究意图之间的路由。识别到论文研究意图时，系统引导用户进入研究项目；进入项目后，
后续步骤由研究工作流控制，不需要每一步重新做全局意图分类。

## 8. 概念数据架构

以下是目标概念模型，字段和表名可在数据库设计阶段调整。

```text
User
 ├─ Conversation
 │   └─ Message
 └─ ResearchProject
     ├─ ResearchQuestion
     ├─ ResearchRun ──> AgentRun / AgentStep
     ├─ ProjectPaper ──> PaperRecord
     ├─ EvidenceCard ──> PaperChunk / source locator
     ├─ ComparisonItem
     └─ ResearchReport
         └─ Citation ──> EvidenceCard
```

关键归属规则：

- `ResearchProject`、证据、比较结果和报告属于当前用户；
- `AgentRun`必须同时关联当前用户和研究项目；
- 公共知识库继续共享；
- 公开论文的规范化元数据可以全局复用；
- 用户私有上传的论文默认只属于当前用户或研究项目；
- 引用不能只保存显示序号，必须关联实际论文和证据记录。

## 9. WebUI 信息架构

目标侧边栏入口：

```text
新建对话
智能对话
知识库问答
论文研究
  ├─ 新建研究项目
  ├─ 进行中的项目
  └─ 已完成的项目
知识库管理
用户与设置
```

研究项目页面采用以下区域：

1. 项目概览：研究问题、范围和进度；
2. 研究计划：子问题、检索式和执行状态；
3. 论文列表：候选、入选、排除、全文状态；
4. 证据中心：按问题、论文和证据类型查看；
5. 论文比较：可配置维度的比较表；
6. 研究报告：编辑、引用跳转、版本和导出；
7. 执行时间线：复用Agent Run/Step展示。

第一版优先保证流程清晰，不进行大规模视觉改版。

## 10. 质量与可观察性

项目的本地可观测性统一采用 Arize Phoenix，不接入 LangSmith 云端。应用通过
OpenTelemetry/OpenInference 将 Trace 发送到本机 Phoenix，默认面向单机开发环境，
Trace 数据保存在本地。

第一阶段观测范围包括：

- 智能对话总图及实际执行分支；
- 意图路由结果与回退原因；
- LangGraph Agent 节点、工具调用、重规划和终态；
- RAG 检索数量、耗时、分数与引用关系；
- LLM 调用耗时、模型信息和可获得的 Token 用量；
- conversation_id、run_id 等关联标识。

Phoenix 接入必须可配置关闭；监控不可用时不能阻断聊天、RAG 或 Agent 主流程。默认不把
密码、令牌、模型隐藏思维链等内容写入 Trace。

论文研究助手至少记录：

- 每次检索的来源、查询和返回数量；
- 论文去重和排除原因；
- 每张证据卡片的来源位置；
- Agent每一步的输入、工具、状态和耗时；
- 报告引用覆盖率；
- 失败、重试和人工修改；
- 模型、Prompt与检索配置版本。

第一版先使用本地 Phoenix 支撑开发调试和最小统计。批量评测、自动质量评分和大规模性能
测试放到业务闭环稳定之后建设。

## 11. 第一版产品边界

### 11.1 第一版必须完成

- 用户可以创建、查看、继续和删除自己的研究项目；
- 输入研究问题后生成并执行研究计划；
- 支持本地知识库、上传论文和ArXiv来源；
- 论文可以去重、筛选和记录状态；
- 能提取带来源位置的证据卡片；
- 能生成论文比较表；
- 能生成带引用的Markdown报告和参考文献；
- Agent运行可以取消、失败后定位问题并继续；
- 刷新或重新登录后研究进度仍存在。

### 11.2 第一版规模假设

- 单个项目重点分析约5至30篇论文；
- 主要面向个人研究，而不是大型团队协作；
- 以单机、本地模型和SQLite运行作为默认环境；
- 优先保证证据可追溯和流程完整，不追求海量论文吞吐。

### 11.3 第一版不做

- 自动代写或自动投稿；
- Multi-Agent协作；
- 知识图谱和GraphRAG；
- 付费数据库的非授权下载；
- 多人实时协作和复杂权限；
- 面向数十万篇论文的独立搜索引擎；
- 完整的云原生集群部署；
- 全自动接受模型生成结论而不展示证据。

## 12. 分阶段建设路线

### 前置架构基础

- 智能对话 LangGraph 总图；
- 本地 Phoenix Trace 与 OpenTelemetry/OpenInference 埋点；
- 观测不可用时的无损降级。

### 阶段A：研究领域基础

- 研究项目、论文记录、项目论文关系、证据和报告数据模型；
- 用户归属与数据库迁移；
- 研究项目CRUD API。

### 阶段B：第一版研究闭环

- 研究计划；
- 多来源检索；
- 去重和筛选；
- 证据提取；
- 论文比较；
- 带引用报告。

### 阶段C：研究模式WebUI

- 研究项目入口；
- 论文、证据和报告页面；
- Agent执行时间线与继续研究。

### 阶段D：检索与引用质量

- 论文结构化解析与页码定位；
- 混合检索、Query Rewrite和Rerank；
- 引用覆盖与证据冲突检查；
- Markdown和BibTeX导出完善。

### 阶段E：评测、观测与部署

- 研究任务评测集；
- 检索、工具选择、引用和报告质量指标；
- 基于 Phoenix Trace 的回归评测和质量分析；
- Docker Compose与运行状态检查。

## 13. 产品完成定义

当用户能够完成以下操作时，可以认为第一版论文研究助手业务场景成立：

1. 登录后创建一个私有研究项目；
2. 提交研究问题并确认研究计划；
3. 系统自动检索并整理一组真实论文；
4. 用户可以查看、纳入或排除论文；
5. 系统从论文原文中生成可定位的证据卡片；
6. 系统根据证据生成论文比较表和带引用报告；
7. 用户可以从报告引用返回论文原文证据；
8. 用户可以中断、刷新、重新登录并继续研究；
9. 研究过程中的失败可以通过Agent时间线定位；
10. 智能对话能够自动选择直接回答或Agent执行，知识库问答和高级调试能力不发生功能回退。

达到以上结果后，项目才能从“具有多个AI功能的练习平台”转变为“拥有明确用户、
完整业务流程和可演示价值的论文研究助手”。
